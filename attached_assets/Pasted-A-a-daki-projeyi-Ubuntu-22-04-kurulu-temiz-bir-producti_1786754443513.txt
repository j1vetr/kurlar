Aşağıdaki projeyi Ubuntu 22.04 kurulu temiz bir production sunucusuna kuracağım.

Sana ayrıca şu iki bilgiyi vereceğim:

* Git Repository: https://github.com/j1vetr/kurlar
* Domain: kurlar.com.tr
* Port : 3001

Sen deployment işlemini kendin yapmayacaksın.

Projeyi detaylı şekilde analiz edeceksin ve bana SSH terminalinde sırayla çalıştıracağım tüm komutları eksiksiz olarak vereceksin.

Amacım verdiğin komutları yukarıdan aşağıya copy/paste ederek projeyi production ortamında ayağa kaldırabilmek.

# 10. PM2 kullanılacak

Uygulamanın process management sistemi olarak PM2 kullan.

Uygulama için manuel olarak:

`/etc/systemd/system/proje.service`

gibi custom systemd service dosyaları OLUŞTURMA.

PM2 kullan.

Tercihen repository root'una:

`ecosystem.config.cjs`

oluştur.

Dosyanın TAM içeriğini bana ver.

PM2 configuration içerisinde uygun şekilde:

* name
* cwd
* script
* args
* NODE_ENV
* PORT
* autorestart
* restart delay
* max memory restart
* log tarihleri

gibi ayarları yap.

Proje npm script üzerinden başlıyorsa PM2'yi ona göre yapılandır.

Sonrasında gereken komutları eksiksiz ver:

```bash
pm2 start ecosystem.config.cjs
pm2 status
pm2 logs
pm2 save
pm2 startup
```

`pm2 startup` çıktısında çalıştırmam gereken komutu da ayrıca belirt.

PM2'nin systemd ile kendi startup servisini oluşturması normaldir.

Ancak uygulama için ayrıca manuel `.service` dosyası oluşturma.

Birden fazla application process varsa mümkün olduğu sürece hepsini aynı PM2 ecosystem dosyası içerisinde yönet.

# 12. Nginx

Nginx reverse proxy configuration oluştur.

EN ÖNEMLİ KURALLARDAN BİRİ:

Nginx configuration dosyasının uzantısı MUTLAKA `.conf` olacak.

Örneğin:

```text
/etc/nginx/sites-available/DOMAIN_ADI.conf
```

oluştur.

Aşağıdaki gibi extension'sız dosya oluşturma:

```text
/etc/nginx/sites-available/DOMAIN_ADI
```

DOĞRU:

```text
/etc/nginx/sites-available/DOMAIN_ADI.conf
```

Symlink de:

```text
/etc/nginx/sites-enabled/DOMAIN_ADI.conf
```

olacak.

Dosyayı oluşturmak için mümkünse bana örneğin:

```bash
nano /etc/nginx/sites-available/DOMAIN_ADI.conf
```

komutunu ver.

Ardından dosyanın TAM içeriğini ver.

Nginx içerisinde gerekli olduğu durumda:

```nginx
proxy_http_version 1.1;
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
```

kullan.

WebSocket varsa:

```nginx
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
```

ayarlarını ekle.

Ancak gereksiz yapılandırma ekleme.

Frontend static SPA ise `root`, `index`, `try_files` yapılandırmasını projeye göre hazırla.

SSR/full-stack uygulamaysa reverse proxy yapısını ona göre kur.

Symlink oluşturma komutunu da ver.

Ardından mutlaka:

```bash
nginx -t
```

ile test et.

Test başarılı olduktan sonra:

```bash
systemctl reload nginx
```

çalıştır.

# 14. SSL

HTTP site çalıştıktan sonra Let's Encrypt SSL kurulumu yap.

Ubuntu 22.04 + Nginx için Certbot kullan.

Gerekli paket ve komutları ver.

Domain ve www için SSL oluştur.

Örneğin uygun olduğu durumda:

```bash
certbot --nginx -d DOMAIN_ADI -d www.DOMAIN_ADI
```

kullan.

HTTP → HTTPS redirect aktif olsun.

Sonrasında SSL renewal testi yap:

```bash
certbot renew --dry-run
```

# 18. deploy.sh oluştur

Production deploy işlemini kolaylaştırmak için:

```text
/var/www/PROJE_ADI/deploy.sh
```

dosyasını hazırla.

Dosyanın TAM içeriğini ver.

Script uygun olduğu durumda:

1. Doğru dizine geçsin.
2. Git'ten son sürümü çeksin.
3. Dependency'leri güncellesin.
4. Migration çalıştırsın.
5. Build alsın.
6. Başarılı olursa PM2 processini reload/restart etsin.
7. Hata oluşursa mümkün olduğunca deployment'ı durdursun.

Script başında:

```bash
set -e
```

ve gerekiyorsa:

```bash
set -euo pipefail
```

kullan.

Ardından:

```bash
chmod +x deploy.sh
```

komutunu ver.

Sonraki deploylarda mümkünse:

```bash
./deploy.sh
```

yeterli olsun.
